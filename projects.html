01LinkCast (Capstone)

Seward County Community College · In development, Fall 2026

Problem
Classroom screen sharing relies on hardware dongles operating point-to-point, one transmitter per display, with no network involvement. Each room needs dedicated hardware.
Approach
Browser-based screen distribution over the campus local network. A lightweight host agent captures the instructor's screen; any browser-capable display joins with an IP address and a short session code.
Tools
  • Python
  • FastAPI
  • MJPEG / WebRTC
  • Vanilla JavaScript
Role
Sole developer. Client discovery and the signed memorandum of understanding are complete; currently in architecture and implementation.
Status
In development for Seward County Community College, Fall 2026.
Reflection
I work for the client, so I assumed I already knew what was needed. Discovery showed me that knowing the organization is not the same as having agreed scope. Next is a working MVP; after that I want to be the one designing infrastructure changes, not just making them.

02Campus Network Operations

Multi-building campus · 2,000+ users

Problem
Multi-building campus network with heterogeneous switching hardware and a large VLAN design serving 2,000+ users.
Work
Configuration and troubleshooting of access switching across approximately 200 VLANs spanning access points, voice, cameras, and physical access control segments.
Tools
  • Aruba AOS-CX 6300M / 6100
  • Cisco Catalyst 2960C / 3750
  • Trunk & access ports
  • RPVST+
  • OSPF (transit VLANs)
  • PoE 802.3af/at
  • LLDP / LLDP-MED
  • SNMPv3
Role
Configuration engineer, independently determining port schemes.
Outcome
Audited a 48-port PoE switch prior to production deployment and delivered a findings report to the CIO identifying:
  • OSPF and transit VLAN mismatches
  • Cameras placed in the default VLAN
  • Missing syslog and TACACS configuration
Reflection
Reading a switch configuration end to end against what the switch is actually for turned up problems no ticket had reported. I want to move toward designing VLAN and routing changes rather than applying ones someone else specified.

03Identity Administration & Incident Response

Hybrid AD + Entra ID · 2,000+ users

Problem
Cloud identity for 2,000+ users across a hybrid Active Directory and Entra ID environment, including authentication incidents and a security compromise.
Tools
  • Microsoft Entra ID (Global Admin)
  • Entra Connect
  • Hybrid join
  • SAML claim mapping
  • Microsoft Graph
  • PowerShell Graph SDK
  • MFA & FIDO2
  • LDAPS
  • AD CS
Role
Primary administrator for the identity domain.
Outcome

During a May 2026 security incident, reviewed four days of audit log exports, identified and removed accounts created during the compromise window, and validated vendor service accounts.

Separately proposed separating the Global Administrator role from daily-use accounts and implementing Privileged Identity Management.

Reflection
The incident was more about reading evidence than changing settings. Knowing what normal looks like in an audit log mattered more than knowing the portal. I am studying for MD-102 and want to end up working in cloud identity.

04Windows Deployment Automation

Tools
  • PowerShell
  • PsExec
  • Dell Image Assist
  • sysprep & unattend.xml
  • Group Policy
  • Active Directory cmdlets
Role
Author of the automation end to end.
Outcome

I wrote the script to save an afternoon. The part that actually mattered was that every machine came out the same. Moving this into Intune and Autopilot is the next step.
